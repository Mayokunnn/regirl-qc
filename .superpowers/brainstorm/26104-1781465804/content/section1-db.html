Section 1 — Database Changes

Two small additions to the existing schema

1. Add instructionRating to criteria results

The CriteriaResult model (nested inside QcSession) gets one new nullable field:

instructionRating   String?   // 'helpful' | 'not_helpful' | null

Populated when the supervisor submits a re-check session for the same wig — they rate the previous session's instructions before the new one starts.

2. Add failureLocation to criteria results

Where on the wig the issue was found — returned by the AI and stored alongside the failure reason.

failureLocation   String?   // e.g. 'front', 'back', 'ends', 'lace', 'crown'

No other schema changes needed

The existing Style, Sku, CaptureAngle, Criterion, ReferenceSet, and ReferenceImage models already match the PRD data model. The hardcoded angles in PhotoUploadScreen will be replaced by API calls — the data is already in the DB from seed.

Migration approach: Single Prisma migration adding two nullable columns to the criteria results table — zero risk to existing data.
